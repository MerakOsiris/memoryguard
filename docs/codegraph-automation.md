# CodeGraph 自动建图

CodeGraph 页提供“新项目默认自动建图”和“当前项目自动建图”两个持久化开关。默认开启，项目单独设置优先；关闭不会删除已建立的图谱。设置按可信共享组隔离，设置文件不可读或损坏时停止自动操作并显示错误。

成功的 Hook/MCP bootstrap 从可信工作目录识别项目，没有图谱时启动独立后台 Python 进程。Hook 退出不影响首次构建。相同项目重复进入不会反复全量重建；成功的文件写入事件触发原有增量刷新。没有代码的目录显示“当前项目没有可索引代码”，后续首次代码写入或页面重试可再次启动。用户主目录、盘符根目录和 MemoryGuard 数据目录不作为自动建图项目。扫描跳过依赖、构建缓存、`.tmp` 和 `.worktrees` 等目录。

页面显示未建图、排队、构建中、就绪、无代码、失败和受阻状态；构建期间自动刷新。超过 10,000 个代码文件会显示明确错误，应选择更具体的项目目录。后台中断不会一直显示“构建中”。已存在的图谱优先于待构建记录显示，兼容迁移前的 scope ID，不重写旧数据。

bootstrap 的 `codegraph` 字段和 Hook 的 `[项目工具]` 段提供简短能力提示，独立于长期记忆候选预算；不会添加长期规则，也不会放宽强制规则预算。Agent 使用 `memoryguard_capabilities(query="codegraph")` 发现操作，再用 `memoryguard_invoke` 调用状态、查询、路径和影响分析工具。

GUI 写入口 `set_codegraph_automation(request)` 接收 `enabled`、`default_policy` 和 `codegraph_project_ref`。它只能由可信桌面管理端调用；项目必须来自已授权来源、已存在图谱或可信 Hook 已登记的项目。手动构建仍可使用。

自动更新由宿主事件驱动，不是后台文件监视器。现有宿主进程可能缓存旧 MCP 配置，需要重连或重启后加载新运行快照。源码修改必须通过正式 provider 安装/修复流程部署，不能仅凭仓库代码认定安装版已生效。

回归覆盖：独立进程首次建图、开关持久化和隔离、关闭停止发布及刷新、无代码目录、迁移图谱可见性、原生 bootstrap/GUI 状态一致、解析诊断不阻断其他文件导入。
