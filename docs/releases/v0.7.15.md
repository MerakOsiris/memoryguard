# MemoryGuard v0.7.15

CodeGraph now builds a project's first graph from a successful trusted
Hook/MCP bootstrap and keeps existing graphs current after supported file-write
events. This release also improves graph navigation and prevents ordinary
CodeGraph queries from copying the entire database into temporary storage.

## Added

- Persistent default and per-project automation switches. The project setting
  takes precedence; disabling automation preserves the existing graph.
- A background process for first builds, with queued, building, ready,
  no-code, failed, and blocked states. Repeated project entry does not rebuild
  an existing graph. Interrupted builds can be retried.
- Bounded CodeGraph capability hints in bootstrap/Hook output, separate from
  the long-term memory budget. Agents can discover operations through
  `memoryguard_capabilities(query="codegraph")`.
- File overview and symbol views, file filtering, aggregated cross-file
  relations, neighbor highlighting, zoom controls, and node details.

## Fixed

- Ordinary graph reads use read-only SQLite connections, including committed
  WAL content, instead of retaining a full database snapshot per process.
  Reads without WAL verify the main file has not changed during the read.
- Validation snapshots and import/install temporary directories live in the
  owning project's or MemoryGuard deployment's cache and are cleaned up when
  the operation ends. Provider installation places runtime snapshots under
  the project/deployment directory and disables pip caching.
- Existing migrated graphs remain discoverable under their original scope
  identities. Parser diagnostics for one file do not block the remaining
  files from being imported.
- Structured file paths display correctly in graph cards and details.

## Upgrade and limits

Upgrade with `python -m pip install --upgrade agent-memguard` and use the
existing provider repair/install workflow to load the new runtime. A running
host may cache its previous MCP configuration; reconnect or restart it after
repair. Updating the package alone does not prove every host has reloaded it.

Automatic updates depend on supported host events. They are not a continuous
filesystem watcher. Automatic first builds exclude dependency/build/cache
directories and reject projects with more than 10,000 code files; select a
more specific directory in that case. Automation does not change mandatory
rule budgets or add long-term rules.
